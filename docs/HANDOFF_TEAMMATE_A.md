## Your deliverables

### 1. `instruction_data/build_instructions.py`

Generate (instruction, response) pairs from the Kaggle dataset. **No LLM
needed for this** — it's pure pandas. Examples of pairs to generate:

| Instruction | Response |
|---|---|
| What was the average salary for ML Engineers in 2025? | The average salary for ML Engineers in 2025 was $X. |
| Which skill was most common for AI Engineers in 2024? | The most common top skill for AI Engineers in 2024 was X. |
| How did Data Scientist salaries change from 2022 to 2026? | Data Scientist salaries went from $X in 2022 to $Y in 2026. |
| What is the highest-paying AI role in 2026? | The highest-paying AI role in 2026 is X with an average salary of $Y. |

**Output format:** a JSON file at `instruction_data/instructions.jsonl`,
one JSON object per line:

```json
{"instruction": "...", "response": "..."}
```

Aim for **200–500 pairs** mechanically generated by iterating over groupings
of the dataframe. Keep the language patterns varied (use 3–5 templates per
question type). Add an `<eos>` token at the end of responses.

### 2. `training/finetune.py`

Supervised fine-tuning loop. Most of this is similar to `pretrain.py`, but
the training data is the (instruction, response) pairs.

Key points:
- Format each example as `<bos>Question: {instruction}\nAnswer: {response}<eos>`
- Compute loss **only on the response tokens** (mask the question with -100
  in `targets` so it's ignored by `cross_entropy(ignore_index=...)`).
  - The model's `pad_token_id` is `0` and the loss already ignores it,
    but for masking the question portion it's cleaner to set those target
    positions to `-100` and call `cross_entropy(..., ignore_index=-100)`.
- Use a much smaller learning rate (e.g. 5e-5) and fewer steps (~500–1000)
- Save the result as `training/checkpoints/finetune_final.pt`

Start by copying `training/pretrain.py` and modifying. Don't reinvent the
wheel — most of the optimizer / scheduler / logging code is identical.

### 3. `eval/evaluate.py`

Two outputs:

**(a) Quantitative:** perplexity on a held-out 10% of the corpus, using
the formula `perplexity = exp(mean cross-entropy loss)`. Report both
pre-train and fine-tune perplexity to show the fine-tuning effect.

**(b) Qualitative:** run a fixed list of ~10 prompts through both models,
print the outputs side-by-side, and save them to `eval/results.md`.
Suggested prompts:

```
"In 2025, a Senior ML Engineer in"
"What was the average salary for"
"The top skill for AI Engineers in 2026"
"Question: Which AI role pays the most?\nAnswer:"
```

The point of (b) is to show in the writeup that fine-tuning meaningfully
changed model behavior (even if the outputs are still imperfect — that's
expected at this scale).

## Tips

- **Don't try to make the model "good."** Your job is to demonstrate the
  fine-tuning + eval *process*, not to produce a polished model. Honest
  results > inflated claims.
- **Save intermediate checkpoints** (every 200 steps) so you can compare
  loss curves.
- **Test on tiny data first.** Make sure your fine-tune loop runs on 5
  examples for 10 steps before scaling up.
- The pre-trained model has a vocab size of 4096, block size of 128, and
  ~3M parameters. Keep these consistent.
